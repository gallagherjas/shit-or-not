# 💩 Shit or Not

[English](README.md) | 简体中文

一个审查代码可维护性的 Agent Skill，关注开发者理解、修改和验证代码时遇到的障碍。

你可以指定整个项目、某个模块或单个文件。审查报告会使用你的语言，列出代码位置、维护成本、影响范围和按优先级排列的改进建议。

## 审查方式

- **系统层：** 检查模块边界、依赖关系、状态归属和变更传播。
- **功能层：** 追踪完整业务链路，检查规则执行、状态转换和失败处理。
- **实现层：** 检查控制流、副作用、重复逻辑、调用契约和验证方式。

## 结论等级

| 等级 | 在已审查范围内的含义 |
|---|---|
| no shit | 开发者能够理解、修改和验证代码。 |
| little shit | 存在维护障碍，但能识别影响边界。 |
| some shit | 某个模块或功能内反复出现相互关联的结构性障碍。 |
| holy shit | 主要模块或代表性链路中反复出现跨边界的维护障碍。 |
| insufficient evidence | 缺少关键代码、上下文或覆盖，无法支持结论。 |
